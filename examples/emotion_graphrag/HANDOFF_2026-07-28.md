## 4. 방법

### 파이프라인 계약

1. **그래프 조회** — `get_node_edges(코드)` → 이름쌍만 반환 → `get_edges_batch()`로 속성 조회 → `keywords=="co_occurs"`만 사용(`belongs_to` 제외) → 수치는 `cooccur_stats["A|B"] = {p_b_given_a, lift, count, weight}`에서. 엣지는 무향+대칭 weight, 방향 정보는 사이드 테이블에만 있음.
2. **벡터 조회** — `chunks_vdb.query(전사, top_k=8)` → `full_doc_id`(=`utt_{clip_id}`) → `labels_map.json` → 유사도 가중 라벨 집계.
3. **융합** — `fused = graph_weight + 0.5 × situational`, 상위 8개(`rules.CANDIDATE_TOP_K`).
4. **LLM 판정** — 후보 전체를 한 번에 제시. 응답 스키마 `{"judgements":[{"code","confidence","evidence"}]}`. 실패 처리 전부 계측(코드펜스 제거 / 파싱 실패 1회 재시도 후 `parse_fail` / 후보 밖 코드는 `hallucinated` / 무응답은 0.0 / clip / 중복은 최댓값).
5. **채택** — `final = detected ∪ {confidence ≥ tau}`. 판정과 채택이 분리 저장되어 tau 변경 시 재호출 불필요.

### arm

| arm | 구성 |
|---|---|
| A0 | Gemini 결과 그대로 |
| A1 | + 같은 대분류 형제 top-8 (그래프 없는 계층 휴리스틱) |
| A2 | + 전역 빈도 top-8 (그래프 없는 빈도 휴리스틱) |
| A3 | + 그래프/상황 후보 top-8, LLM 없음 |
| A4 | + judge, 후보 48개 전체·근거 없음 (**그래프 없는 LLM 대조군**) |
| A5 | + judge, 그래프 후보 8개·근거 주입 (**전체 시스템**) |

A4와 A5는 프롬프트가 동일하고 `[후보와 근거]` 블록만 다름 → A5−A4가 그래프 기여분.

### tau 프로토콜 (테스트셋 오염 방지)

before holdout 31에서만 스윕 → **A5 τ=0.50, A4 τ=0.60** 확정 → before 100건 전체로 그래프 재빌드 → 테스트 배치에 1회 적용.

## 5. 결과 (테스트 = last 100건)

### accept tier (주지표)

| arm | Jaccard | Recall | Precision | 평균 예측 | cross-major |
|---|---|---|---|---|---|
| A0 | 0.285 | 0.436 | 0.422 | 3.17 | 0.000 |
| A1 | 0.211 | 0.648 | 0.231 | 9.08 | 0.000 |
| A2 | 0.175 | 0.728 | 0.188 | 11.17 | 0.553 |
| A3 | 0.187 | 0.710 | 0.198 | 10.91 | 0.379 |
| A4 | **0.307** | 0.633 | 0.357 | 5.38 | 0.262 |
| A5 | 0.303 | 0.547 | 0.379 | 4.24 | 0.117 |

paired bootstrap 95% CI (클립 짝지어 5000회):
- **A5 − A4 = −0.004 [−0.031, +0.022] → 유의차 없음**
- A5 − A0 = +0.018 [−0.009, +0.045] → 유의차 없음
- A3 − A0 = −0.098 [−0.139, −0.059] → **유의하게 하락**
- A5 − A3 = +0.115 [+0.082, +0.149] → **유의하게 상승**

### 다른 tier

- target: A0 0.213이 최고. 어떤 arm도 A0를 유의하게 못 이김 (A5 0.199).
- union: A4 0.337 > A5 0.306. **A5−A4 = −0.031 [−0.054, −0.010] → 유의하게 A4 우세.**

### 효율

| | A4 | A5 |
|---|---|---|
| 클립당 판정 후보 | 44.8개 | 7.7개 |
| 총 판정 | 4,483 | 773 |
| parse_fail / 환각 | 0 / 0 | 0 / 0 |

confidence 구간별 적중률은 **전 구간에서 A5 > A4** (예: [0.3,0.5) 0.306 vs 0.090, [0.7,1.0] 0.412 vs 0.299).

### 결론

1. **그래프가 LLM 대비 정확도 우위를 입증하지 못했다.** A5≈A4(accept), union에서는 A5가 유의하게 열세.
2. **그래프의 측정된 이득은 효율과 보정.** 판정 부하 5.8배 절감, 동일 confidence의 신뢰도 상승, 환각 구조적 차단.
3. **성능 상승은 judge에서 나왔다.** A3는 A0보다 유의하게 나쁘고(재현율↑ 정밀도↓), judge를 붙여야 회복된다. judge는 향상 장치가 아니라 **후보 폭주 억제 장치**.
4. **후보 단계에서 그래프가 빈도 baseline에 졌다.** 재현율 A3 0.710 < A2 0.728, cross-major A3 0.379 < A2 0.553.
5. **tier 선택이 결론을 지배한다.** target에선 아무것도 A0를 못 이기고, union에선 A0 빼고 다 이긴다.

## 7. 미해결 / 다음 단계

### 발견된 구조적 문제: 그래프에 감정밖에 없다

현재 그래프 = 노드 54개 전부 감정(EmotionMajor 6 + EmotionMinor 48), 엣지 2종(belongs_to 48, co_occurs 149). 발화·화자·상황·비언어 단서 노드가 **하나도 없다**.

`co_occurs`는 **전역 테이블**이라 발화가 달라져도 후보가 안 바뀐다(detected 집합이 같으면 동일 후보). 결국 A2(전역 빈도)와 같은 종류의 사전지식이라 성능이 붙는 게 구조적 귀결.

DESIGN.md에서 보류된 것: 선2(상황→감정, `original_major_code` 오염), cue_indicates(cue 라벨 없음), 2층 화자 개인화(화자 대부분 1~2클립).

### 세그먼트 평탄화 (가장 유력한 개선 후보)

Gemini JSON은 세그먼트별로 감정·강도·운율을 주는데, 현재 `labels_kr._load_gemini()`가 **클립 단위 합집합**으로 뭉갠다. 잃는 것: 시간 순서, 동시성, 강도, 근거 문장.

부작용: co_occurs 집계가 오염된다. 세그먼트 4개짜리 클립이면 C(8,2)=28쌍이 공존으로 들어가는데 실제 동시 발생은 8쌍뿐 — **나머지 20쌍은 노이즈**. judge 프롬프트도 서로 모순되는 운율 서술이 한 줄로 이어붙어 들어간다(judge 보수성의 원인 후보).

개선안 (난이도순):
- **A. 공존 집계를 세그먼트 단위로** — `labels_kr.to_aggregate_rows()` 근처 한 곳 수정. 다만 세그먼트 1개인 클립이 before 60%라 엣지가 149개보다 줄어들 수 있음
- B. 후보 생성을 세그먼트별로 하고 마지막에 클립 단위로 합쳐 채점
- C. judge를 세그먼트별로 (LLM 호출 1.8배)
- D. 감정 전이 엣지(`평온→결의`) 신규 타입

### 지금 데이터로 가능한 신규 신호 (가용성 확인 완료)

| 신호 | 가용성 | 비고 |
|---|---|---|

### 우선순위 제안

1. **후보 생성 개선** — 병목은 judge가 아니라 후보다. 빈도 baseline에 지는 상태부터 해결. (세그먼트 단위 재집계 / 2-hop / lift·Wilson 임계 재탐색)
2. **그래프 고유 가치 재정의** — cross-major에서 빈도 baseline에 진 이상, "복합감정 회수"를 우위 영역으로 주장하려면 근거 필요. 조건 B(논문 유래 엣지) 검토
3. **A5를 개별 라벨러 대비로 재측정** — 보고서 수치(집계 gold 대비 0.303)와 기준선(원본 집합 대비 0.206/0.256)은 척도가 달라 직접 비교 불가. **보정 후 제미나이가 사람 순위 안에 들어가는지**를 같은 척도로 재는 것이 가장 설득력 있는 그림
4. **tier 합의** — 팀에서 어느 tier를 정답으로 쓸지 결정 필요

## 9. 작업 시 주의사항

- **arm 비교는 paired로.** 절대 수치는 배치 의존적이다.
- **tau를 테스트셋에서 고르지 말 것.** 튜닝셋에서 확정 후 1회 적용.
- **KG를 특정 라벨러 1인 데이터로 만들지 말 것** (과적합 우려로 명시적으로 배제된 방향).
- `parse_fail` / `hallucinated`는 항상 리포트에 포함. LLM이 응답을 못 뱉은 걸 "회수율 낮음"으로 오독하면 안 된다.
- A4는 후보 48개라 프롬프트가 길고 느리다. 순차 실행 시 31클립에 33분. `--concurrency 8` 필수.
- 결과를 낙관적으로 각색하지 말 것. 이번 실험의 핵심 결과는 "그래프가 LLM 대비 우위를 입증하지 못했다"이며, 이 점을 흐리는 서술은 하지 않는다.
